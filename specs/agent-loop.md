# agent 循环增强 — 行为契约

覆盖三件事：**并行工具调用**、**循环检测**、**工具描述**。

## 1. 并行工具调用

### 背景

一轮模型回复可能带多个 `tool_calls`。现状是**串行** for 循环，互相独立的只读调用平白互相等待。

### 规则

- 一轮内的多个 `tool_calls` 分两类：
  - **可并发**：工具在 `allowed` 内 **且** `planSafe === true`（只读、无副作用）。
  - **须串行**：其余（写/删/bash/ask/记忆写入…）——它们可能触发 confirm 或产生顺序敏感的副作用。
- **整批**处理：当该轮**全部** `tool_calls` 都属可并发类 → 用 `Promise.all` 并发执行；
  只要有一个属于须串行类 → **整批串行**（保持与现状一致的确定顺序）。
- `ask` 永不并发（一次只允许一个待答问题）。

### 事件顺序（必须确定）

1. 先按模型给出的顺序，为**每个** call 追加 `tool.call` 事件并推送 UI；
2. 再执行（并发或串行）；
3. 最后**按原顺序**追加 `tool.result` 事件并推送 UI。

即事件顺序与模型给出的顺序一致，并发**不影响**事件序（也不影响 `messages()` 投影的合法性：
所有 `tool.result` 仍排在同一 `assistant(tool_calls)` 之后）。

## 2. 循环检测

### 背景

模型可能反复以**完全相同的参数**调用同一工具（读同一个文件、跑同一条命令），空转烧 token。
现状只有 `MAX_TURNS`（50）兜底，太晚。

### 规则

- 在**单次 `agentLoop` 调用内**统计 `tool_name + 规范化 JSON 参数` 的出现次数。
- 第 **4 次及以后**，在该次 `tool.result` 文本**末尾**追加提示：

```
[提示] 你已用相同参数调用 <tool> 第 N 次。请改变策略、换参数，或向用户澄清后继续。
```

- **不阻止执行**（工具照常运行）——由模型自行纠正；`MAX_TURNS` 仍是最终兜底。
- 计数跨轮次累计（同一 turn 内多次模型请求共享）。
- 参数规范化：`JSON.stringify` 解析后再序列化（键序稳定）；参数解析失败则用原始字符串。

## 3. 工具描述（工具选择质量）

### 背景

`toolSpecOf` 现用 `cmd.title` 当 description（"读取文件"）——模型无从知道**何时该用、何时不该用**，选工具准确率受限。

### 规则

- `Command` 新增可选字段 **`description?: string`**，语义是「**何时用 / 何时不用**」，一句话。
- `toolSpecOf` 的 `description` = `cmd.description ?? cmd.title`（缺省向后兼容）。
- 所有内置命令补 `description`，明确其边界与替代关系（例如 `file_edit` 提示"改文件优先用它而不是 file_write"）。
